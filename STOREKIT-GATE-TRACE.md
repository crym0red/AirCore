# StoreKit / Premium Gate Static Trace — v9

This read-only educational analysis adds three layers to the existing function-level StoreKit trace:

- **CFG basic-block reconstruction:** creates block leaders from direct branch targets and fall-throughs, lists each block's address range, exit kind, successor addresses, and predecessor count.
- **Bounded register/condition definition hints:** for CBZ/CBNZ/TBZ/TBNZ, searches backward for a textual destination-register definition; for B.cond, searches for a nearby flag-setting compare/test. This is intentionally labeled a heuristic, not SSA or symbolic execution.
- **Direct call-edge map:** records direct `BL` instructions in the containing function and resolves targets against Mach-O import stubs and symbols when available. This provides cross-function navigation leads but does not recursively execute/decompile callees or propagate values between functions.

The existing local Mach-O decoding and branch candidate list remain. No code bytes are changed and no patch artifact is generated by this analysis view.

## Known limitations

- CFG edges for indirect branches, exception paths, tail-call patterns, and compiler-generated async dispatch may be missing.
- Register definitions are inferred from printed operands and can be wrong for aliases, partial-register writes, load/store semantics, and instructions with implicit operands.
- A `BL` target is not necessarily a premium-related function; call edges are navigation evidence only.
- Swift async state machines, Objective-C dispatch, block/closure captures, and interprocedural data flow are not fully reconstructed.
- Static evidence does not establish runtime reachability, transaction validity, or server-side authorization.

## Validation

The changed Swift files were parsed with the available Swift frontend. A full Xcode/iOS compile and on-device validation were not available in this environment.
